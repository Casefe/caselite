# ADR-023｜已保存正文的固定交付快照

- Issue：DEV-1628；用户于2026-11-08明确授权真实固定快照、幂等和退出重开验收。
- 基线：7100152；适用现行02/03/05/06，DEV-1737界面沿用。
- 状态：已实现并完成本地技术验证与独立复核，待律师业务验收。

快照由现有 Task/Document Owner 经 task:v1、Application 和同一 SQLite 连接创建。0017 仅增加 deliverable_snapshots，引用现有 body_revisions 的二进制修订，不复制正文、不改变Yjs格式、不建第二运行时。只允许当前已保存、未归档修订，校验task/document/body绑定、正文修订、Document元数据版本与Task版本。host固定标题、分类、标签、SHA-256、说明、创建时间与本机操作者；所有快照均标草稿，不等于正式定稿、任务完成或送达。

当前正文白名单不接受SourceRef节点，来源清单明确为空；快照不会自动包含Task材料或Agent历史。后续引用格式需由来源/正文Owner另行准入，不能由renderer补入未核验来源。

创建快照、必要task_activity及原task_receipts同一IMMEDIATE事务。原请求摘要不变；新增操作不接收renderer正文。相同幂等键重放返回原结果；同一Document/body修订/元数据版本/Task版本只建一份快照，即使新键重复点击也复用原版本及说明，不再写第二条业务活动。新键的成功回执仍记录原快照ID。未知结果先读原键；查无回执后才允许用原请求重试。

快照和被引用正文修订由增量SQL触发器禁止覆盖/删除，外键保持同版本绑定；读取固定修订并核验hash，失败可见，不降级为最新正文。列举和读取均检查当前workspace及Task/Document绑定；归档后只读已有快照，不再创建新快照。

复用DeliveryVersions界面；真实适配器只经原Preload task入口。提交已确认但刷新失败时只重读，不再次创建。切换文档/快照使旧查询失效；未决提交锁住导航，原编辑器不因查看交付版本而卸载丢输入。Word/PDF按钮由后续消费卡启用，本卡不伪造输出成功。

验证要求：旧库升级不丢原对象/正文/回执，v2不改变固定v1，重复键/新键重复、同键改内容、跨workspace/错绑定、过期元数据/正文、归档、事务中活动/回执故障回滚、只读失败、hash错误、重启/强退重开。包内同入口与SQLite证据相互核验。独立复核实际diff及适用证据。

回退保留0017、快照行和正文读取能力。旧客户端不支持新操作时拒绝，禁止原库就地降级或删除快照。撤去新建入口不代表可以丢弃已有快照；恢复旧备份须在独立副本核对恢复点和后续写入。
