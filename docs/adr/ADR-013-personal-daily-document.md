# ADR-013｜个人每日 Document 与首页备忘录

- 状态：提议
- 日期：2026-11-06
- Linear Issue：[DEV-1689](https://linear.app/logixy-ai/issue/DEV-1689)
- 影响模块：Document、SQLite 迁移、Application/IPC、Tiptap/Yjs、首页
- 责任与人工确认：谭辉于 2026-11-06 确认按每日备忘录提案推进；存储迁移、失败恢复和独立技术复核仍须实证，用户体验另行接收。
- 代码位置与提交：本 ADR 为提议；产品实现尚未交付。

## 背景与问题

律师需要在首页记录每日个人笔记，不必先创建任务；同一天可重开，历史日期可查。当前 `documents.task_id` 非空且唯一，任务正文的查询与保存均绑定 Task。已有 `body_revisions` 保存完整 Yjs 二进制修订，不能通过伪造 Task 或另建纯文本笔记绕开唯一正文 Owner。DEV-1689 的个人作用域和 DEV-1599/1623 的真实前置应逐项核对；现有 Task 成功演示不证明个人笔记已能恢复。

## 必须满足的不变量

- 正文仍由 Document/body 与 `body_revisions` 的 Yjs 二进制唯一持有；列表和日期仅是元数据，Renderer 不得访问 SQLite 或文件路径。
- 每项个人笔记有稳定 Document/body 身份、工作区作用域和明确所有者类型；Task Document 必须有且仅有一个有效 Task，个人 Document 不得绑定 Task。受控查询、保存和回执均验证作用域与绑定。
- 同一工作区、个人、日期和日期归属时区最多一条记录。创建、重复请求及回执未知恢复不得生成重复 Document；引用、版本与幂等结果在同一 SQLite 事务提交。
- 保存以期望修订拒绝旧快照，ACK 只确认对应的 body 和修订；失败、冲突及迟到 ACK 保留当前输入，禁止伪报成功或覆盖已保存修订。
- 笔记不自动发送至模型，不自动创建 Task，不引入 localStorage、第二编辑器、第二正文库或新同步服务。
- 迁移必须保全全部旧任务、Document、body、关联、外键和修订；旧程序不应对新结构静默写入。备份、兼容性、失败恢复、空间及回退须单独实测。

## 候选方案

| 方案                                                                      | 优势                                 | 风险/成本                                                     | 证据                                                                         |
| ------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| A：扩展现有 Document，个人作用域与 Task 绑定互斥，日期索引只引用 Document | 复用 Yjs 与现有正文身份；不虚构 Task | SQLite 表重建、旧版本兼容、公共接口与权限检查需严格迁移及负测 | 当前 `packages/local-db/src/schema.ts` 和 `task-store.ts`；迁移 Spike 待执行 |
| B：每份笔记隐藏创建一个 Task                                              | 可复用已有 Task 保存                 | 把个人记录伪装成业务任务，污染列表与 Activity，不符合用户结果 | 当前 Task/Document 一对一结构                                                |
| C：独立 Note 正文库或 localStorage                                        | 实现局部简单                         | 形成第二正文真源并绕开受控保存恢复                            | 不满足现行02/03与 DEV-1689                                                   |

## 拟定方向

用户确认按每日记录方案推进；拟优先验证 A，拒绝 B、C。该确认不等于本 ADR 已验证，也不取消 DEV-1599/1623 的依赖、旧数据迁移、独立技术复核及人工体验接收。

具体候选是以 CHECK 约束实现 Task 与 personal 两种互斥绑定，为 personal 明确 workspace/owner；日期索引通过 Document ID 引用同一正文。日期索引不能仅外键引用 Document ID，还须约束 Document 类型与 workspace/owner 一致；候选为包含 Document ID、类型、workspace 和 owner 的复合外键，并由 Application 再执行授权校验。现有任务的 Task ID、Document ID、body ID、修订及外键在迁移前后必须一致。现有消费者中按 Task JOIN 的查询必须保持结果和授权语义；个人记录不得泄漏到任务文档列表。具体字段、迁移顺序和实际 SQLite 外键行为以 Spike 与实现评审为准，不将草图视作现成 Schema。

## 日期及交互语义

使用设备本地日期与 IANA 时区标识创建/查找当天记录。应用启动时按需创建；运行中跨午夜，先确认旧记录已保存或保留可恢复输入，再切换到当天。应用关闭期间不运行后台服务，重开时补建当天，不批量补空白历史日。时区变更不移动、覆盖或合并旧记录；新日期/时区键生成自己的记录。历史选择显示其记录日期和原归属时区。设备时钟倒退、重复键、DST 和时区不可获取须作为失败或正反例验证，不能用固定 24 小时计算下一次午夜。

首页右栏为个人大纲入口，复用现有编辑器扩展及 Yjs；支持列表层级、输入、保存状态和旧日回看。实际编辑与已确认落盘分开，未经持久化回执不显示保存成功；关闭应用和切日的失败/未确认状态必须可解释。

## 验证与交付

- 隔离数据库 Spike：2026-11-06 用本机 Python SQLite 3.53.0 在临时合成数据库执行仓库 0000—0004 SQL，并实验表重建；旧 Task、Document/body 标识与一段合成修订字节保持，`foreign_key_check` 无错误，5 项无效绑定/日期重复被拒。第一版仅引用 Document ID 的日期索引错误地接受了 Task Document，记为 FAIL；复合类型和作用域外键的第二版分别拒绝 Task 文档、跨工作区、跨用户三项反例，并接受正确个人绑定。合成库位于 `/var/folders/wv/614rfdyd1x1_s30jg7mvf3mr0000gn/T/caselite-personal-spike-7p9qh2yp/spike.sqlite`，仅供本机临时复核，不含客户内容。此为原生 SQLite 约束试验，不是正式 Drizzle 迁移、产品权限、Yjs 或恢复测试；故障回滚及完整迁移尚未验证。
- 隔离事务故障试验：在同一合成数据库中模拟表重命名及重建后、提交前抛错，显式回滚后旧表和一条旧记录仍可读取，外键检查无错误；真实迁移执行器、崩溃和磁盘故障仍未验证。可通过 `python3 scripts/spike-personal-document.py` 重跑互斥绑定、复合作用域外键、旧数据和事务回滚实验；脚本使用系统临时目录，不打开产品数据。
- 产品工程：同键重试/回执未知、并发及日期唯一；越权、错误绑定、旧 Schema、存储失败、旧修订与晚到 ACK；真实迁移、备份和恢复。
- 桌面：合成数据验证中文输入、层级列表、空白、保存、日期切换、退出重启、强退与失败恢复；分别记录真实、模拟及未运行项。
- 专业复核：存储迁移、权限、备份和恢复由独立上下文依据真实 Diff、合同和日志复核；不可仅凭模型自评放行。
- 回退：先验证一致性备份与隔离恢复；有个人数据后的回退不能只换旧二进制或删除列。版本不兼容时停止写入并保留数据，优先前进修复；回退/恢复方案未经实测不得宣称可用。

## 后果与重新评估

日期索引、迁移及独立作用域增加实现与验证成本；同步、多用户、自动日程提醒、附件、笔记转换及导出均不因本 ADR 自动启用。若需跨设备按统一日期、改变时区策略、调整正文格式或添加共享权限，须重新审查相应合同及迁移。
