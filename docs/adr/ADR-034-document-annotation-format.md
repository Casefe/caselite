# ADR-034｜文档正文高亮与批注格式

- 状态：DEV-1851 实施；2026-11-10
- 批准：用户要求按已确认模拟图实现高亮、批注、保存重开恢复，测试后合并；不包含云服务或外发批注。
- 基线：b52c52c7490d5478634e79cfb0fb1095b0f94152（与 main 99bd5eb 同树）。现行02/03/06及其版本见 Issue。

## 决定与兼容

既有 Document/BodyRevision 的 Yjs 二进制仍是正文唯一真源。新增 editor_schema=2：沿用所有版本1节点、表格及格式，增加固定黄色 highlight mark（无属性）与 comment mark（id 为 UUID，text 为非空去首尾空格的纯文本，最多4000字符）。同一批注可跨文本片段，id 相同则内容必须一致；最多200个不同批注。服务端验证所有输入，沿用2MB及结构复杂度上限。不是任务讨论 Comment，也不引入第二套批注数据库、正文、依赖或外部服务。

首次新增标记时升级1→2。保存沿用 task:v1、预期修订、同事务正文/格式/回执/事件和未知结果核对；不允许2→1，删除所有标记仍保留格式2。旧程序拒绝格式2且保留二进制，回退代码不能降级用户数据。编辑器以公开 Mark API 独立实现，文本由 React 转义，DOM 仅固定样式和批注ID，不注入批注HTML。

固定交付表当前仅接受格式1，故新工作稿2创建快照明确返回兼容提示，不能静默删除标记。原格式1固定快照仍可读取、Word/PDF导出且内容不变。本轮不改DDL或原件。单段AI写回仍仅支持格式1，格式2禁用该入口；页面AI引用只派生正文纯文本，不包含批注内容。

## R2 验证与回退

实施前后用真实 SQLite 测试：旧稿可读、标记格式严格拒绝、格式升级与重新打开、旧键重放、事务失败回退、降级拒绝、旧固定快照不变及新格式交付拒绝。随后真实 Electron 选择/高亮/新增修改删除批注、保存退出重开、撤销与双栏单写入者。独立上下文依据实际diff和证据审查；工程通过不代替律师验收。

回退仅 revert 本Issue提交，保留数据库和正文2字节，不删除用户标记；旧程序会提示不兼容。恢复升级版即可读取，不能通过导出纯文本或重写旧稿模拟回退。
