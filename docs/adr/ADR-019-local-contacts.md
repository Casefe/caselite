# ADR-019｜本机联系人与项目关联

DEV-1806 首版。联系人由同一 SQLite 连接里的独立适配器管理，通过受控 Application 和工作区 IPC 读写。采用联系人、关联表和原提交回执，同事务保存。跨项目可引用同一联系人，关联不推定客户或付款方身份。未采用项目内重复文本、浏览器本地存储和可自动合并的姓名键。

迁移 0016 只新增表。客户端提交带期望版本、记录 ID 和原提交身份。确认失败重用原提交，内容改变必须取得新身份。工作区和项目 ID 在事务内核对。首版联系人信息不进入 Agent、日志或网络；客户增量的显式发送边界见下。

回退 UI 与宿主接线时保留 SQLite 表和已提交数据。引入客户角色、共享、合并或出站功能时重新审查权限、审计和数据恢复。

## DEV-1806｜2026-11-10 客户轻量工作区增量

用户确认客户页设计及测试后同步开发主目录/GitHub。界面“客户”复用原联系人身份，不推定委托/付款/权限身份，不新增CRM。0027增量增加基本资料字段、联系记录/备注元数据和既有Task/Document关系；旧请求省略新增字段时保留已有值，原0016回执摘要仍可核对。数据Owner仍是同一SQLite连接下contacts适配器，不复制项目、任务或文档。

记录/备注的可编辑正文使用原body_revisions和default Yjs Schema；结构化条目保存body_id/修订，读取文本仅从固定Yjs修订派生。条目、正文和原提交回执在同一事务落盘；版本冲突、跨工作区、错误来源或未知回执不得转为新提交。旧修订保留，回退代码不删除0027表/列或正文。

客户作为既有Pi/assistant-ui链路的新scope `contact:<uuid>`，复用InspectorLayout、SidebarAgent、AgentPanel及公共样式。原agent_runs仍是唯一运行历史；JSON使用既有扩展scope兼容编码，回退版只读占位终态，新版从scope列恢复真实身份。客户页引用只含当前名称/个人组织类型，不自动外发电话、邮箱、历史、项目/文档材料。显式发送才调用原Provider；用户点击候选“继续修改”后，输入框展示可移除的引用，再显式发送才引用本客户的那个成功候选，不按关键词自动选择，不拼接全段聊天。未知发送保留原引用身份，迟到回执不能清除较新的选择。

Application 从原始输出派生可选 contact_record_candidate DTO，复用唯一候选 Schema；先剔除历史派生字段，只向有权访问的客户 scope 返回成功且完整的合法候选，不修改持久 Run 或序列。Renderer 只消费已通过 Main/Preload 校验的 DTO；保存仍重读持久 Run，DTO 本身不是保存授权。

普通问题正常回答，沟通记录请求返回严格有界JSON候选；模型输出不是正式客户记录。用户在同一对话点击保存，经原Application与workspace/scope、Run成功终态和来源校验后，事务保存Yjs正文及来源Run ID。一条Run只可形成一条正式记录；取消、失败、不完整或另一客户Run不可接受。继续补充已保存候选可保存为新的补充记录，不静默覆盖原记录。没有新增第二Runtime、正文库、模型依赖、聊天抓取或自动通知。

资料和关联表单在编辑开始时冻结值及期望版本，详情未完整读到时不能开始编辑；各编辑模式互斥。未知提交在 QueryClient 工作区生命周期内独立保留原请求，核对入口在表单分支外，面板卸载重挂后仍按原身份恢复；确定回执安装到缓存后才解除阻塞。资料、各类关联及记录分别有失败/空态和同身份重试；无结果时保留草稿并阻止更换目标。测试使用合成资料和Mock Provider；真实收费调用和律师验收分别记录，不以CI或静态模拟图代替。

## DEV-1806｜2026-11-10 最简联系人与原位编辑

用户确认以“联系人”统一界面命名，覆盖个人、组织及司法工作联系人；既有客户名称、关系标签和历史资料保留。共用资料只有姓名／名称、类型、电话、微信、邮箱、地址，单位与职务折叠选填，标签可选。不引入诉讼身份资料页，项目中的当事人角色不写入全局档案。

0029 为追加迁移：地址默认空字符串，旧 city 不推定为完整地址；旧客户端省略 address 时保留现值，原回执摘要不增加缺席字段。原位编辑冻结起始版本，Enter／失焦共用提交锁，Esc 取消，未知结果只核对原请求，冲突保留本地输入并由用户显式采用最新版本继续。列表与详情共享同一属性栏和 AI 实例，双击打开详情，返回保留原筛选、分页、顺序、滚动与焦点；刷新失败保留已确认资料及本地表单。

统一往来按原始来源组合既有沟通记录、显式关联的 Run、材料、收款及关联任务活动，不复制对话或财务正文。联系人 SQLite 仅拥有 contact_source_links 关系。Run 保存其真实 scope，材料保存 Task scope，收款保存 Project scope；联系人 IPC 注入可信窗口 Owner，经原 Agent／Material／Finance Application 核验后才读写。整组核验失败不替换关系，版本、关系和回执同一事务。来源不可读时隐藏对应内容并提示部分失败，不伪装同步成功；原始来源仍由各自 Owner 管理。

关联不证明参与人、提交人或付款人；未知材料时间明确展示未记录。相同材料去重，已转正式沟通记录的 Run 不重复显示，任务活动分批加载。跨 scope Run 只能作为引用读取，不能绕过原 save_entry 的同联系人成功 Run 限制。微信截图复用现有任务材料入口，不以联系人 ID 假冒 Task，不宣称已实现微信自动连接。没有新增监控 Agent、CRM、Runtime、状态框架、自动收费调用或材料外发。

验证使用合成工作区、Mock Provider、原生 Electron 写入／重启读回及保留式验收启动器。回退代码保留新增列、关系和旧正文修订；升级前备份验收快照，不重置客户样例、用户修改或凭据。该记录不替代真实测试输出或律师业务验收。
