## 问题及不变量

`legal/LICENSE.md`、`legal/EULA.md` 是两份协议正文的唯一仓库来源，根 LICENSE.md 仅提供定位。用户指定许可方谭律师、邮箱 tanhui277@163.com、生效日期2026年11月9日。正常办案、收费法律服务和成果交付允许；软件销售、外部分发、改名经营与外部托管须另获授权。第三方许可、历史有效授权和法定例外保留。

普通启动不得在确认前注册业务IPC、打开案件库、读取模型凭据或初始化Agent。独立窗口仅持有协议专用Preload，Renderer只收全文及摘要，不能读取路径、SQLite或秘密；IPC只信任该窗口的主Frame，不能用“任意活窗口”授权。用户可拒绝、关闭或退出，不得默认勾选。

## 方案与选择

| 方案                                               | 结论                                                              |
| -------------------------------------------------- | ----------------------------------------------------------------- |
| 在工作台上盖一个弹窗                               | 放弃：业务组件、数据与IPC已经初始化，容易漏掉绕过入口             |
| 原生消息框承载两份长文                             | 放弃：全文阅读、切换和明确确认不易验证                            |
| 同一Forge构建内的独立窗口＋最小专用IPC/Application | 本次实现：先完成确认，再进入现有启动路径，不引入另一Runtime或依赖 |

采用既有ADR-012设备配置的职责模式：Main适配器拥有 `userData/legal-acceptance.json`，Application负责当前文本匹配、输入校验与保存回读。它是安装实例/本机OS账户下的启动配置，不是工作区/案件/法律业务对象，不进入SQLite/Yjs、不与案件资料同步、不成为第二业务真源。文件只含格式版本、两份正文SHA-256、组合摘要和本机确认时间；不记录案件、姓名、设备指纹、密钥，不外发。

正文从Forge复制的 `Resources/legal/` 按固定文件名读取，开发态从仓库 `legal/` 读取；哈希针对原始UTF-8字节。两份正文任何变化都重新确认，不以软件版本号替代文本匹配。文件缺失或存储故障不放行；未知格式/损坏记录保留并提示支持，不自动覆盖。明确同意后临时文件独占写入、fsync、原子rename、同步目录，再经Application回读确认。关闭/拒绝无写入；失败留在窗口可重试。

页面将正文作为文本和有限标题/加粗标签呈现，不解释HTML或链接；生产CSP禁网，拦截导航、弹窗、webview，保持sandbox/contextIsolation。分别阅读至文末并标记、主动勾选后提交当前组合摘要及两份确认。阅读进度只辅助交互，不能证明实际理解；本机记录不作为实名、组织签章、防篡改或不可抵赖证据。

## 工程验证边界

既有SQLite/PDF/离线集成探针在明确隔离的非产品分支运行，不进入业务工作台，不产生普通用户接受记录。其他既有合成Task演练通过同一协议窗口真实执行自动点击，目录仍经过既有临时根校验；其动作仅为合成验收，不能宣称律师本人同意。新增legal-*阶段验证首次、重复、文本摘要变化、拒绝、关闭及保存故障；只有legal-preview阶段交还给用户操作。
