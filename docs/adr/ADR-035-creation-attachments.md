# ADR-035｜创建弹窗的共用交互与附件暂存

- 状态：DEV-1883 实施决定，产品验收待完成
- 日期：2026-11-11
- 用户授权：确认任务/日程 V2 模拟图并要求开发、更新工程约定

创建界面共用交互构件，领域字段、校验、权限和写入仍归原 Application。日历任务入口直接复用 TaskCreateDialog；日程是同一 Task 的时间优先创建布局，不产生第二日程对象。初始日历元数据沿可选 create 字段，与任务及幂等回执在原 SQLite 事务保存，旧请求摘要不增加缺省字段。

创建前附件复用 MaterialFilesPort 与 material_stages。新增 kind=creation 的有界工作流记录，只有草稿 ID、状态、附件 token 和创建后 Task ID；不保存正文或第二份原件。普通 stage 查询排除此标记。原文件仍以原 token、hash 和不可变来源登记。无需新表或依赖。

流程为受控单文件选择、逐次追加、创建 Task 时同事务一次绑定暂存、逐项沿原 commit 保存、最终确认。绑定只能发生一次，绑定后不得更换 Task 或丢弃已创建对象。部分失败保留原 Task 和 token，继续保存不重建任务；重启可恢复待保存附件。取消仅清理本草稿的未提交暂存。不会用 home 入口制造隐藏任务，不自动加入 AI 选材。上限与格式沿共享合同，保留已撤回批量/文件夹入口的决定。

元数据变更使用现有 SQLite 事务；跨介质仍使用原 stage→hash→place→commit 恢复机制，只有真实回执才确认保存。必须验证取消、格式/大小、部分失败、重复绑定、重启、旧单份/批次兼容以及旧创建回执。Renderer 只持不透明 ID，不持任意文件路径。

本轮不重写项目、文档、财务、联系人表单。后续按真实消费者采用共用外壳与附件控件，各自读写 Owner 保持。回退入口须保留 creation 标记的识别、Task/来源/原件读取及未完成附件的恢复方式，不能直接降级删除新记录。

参考：前轮 Plane、Huly、WeKan、OpenProject、Leantime 研究仅借鉴分层机制，无第三方源码采用。验证结果与被测 SHA 见 DEV-1883 交付记录。
