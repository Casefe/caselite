# ADR-033｜共享导出样式与固定产物身份

DEV-1629，用户 ULYSSES-EXPORT-AUTH-2026-11-09；基线84df2c8。状态：实施中，不能据此宣称设置、预览或双格式已通过。

## 决定与唯一数据 Owner

纸张、字体、字号、四边页边距、基础页眉页脚组成有版本的严格结构化样式。复用当前工作区 local_preferences JSON、Application/typed IPC、预期版本及原键回执，不新增偏好真源或浏览器存储。省略可选字段的旧请求保留已保存值，且摘要仍从原请求计算。日历等局部操作不得顺带提交或清掉导出草稿。正文与固定交付快照仍由现有 Yjs/SQLite Owner 管理，样式不改正文结构。

最终导出由宿主从样式白名单解析生效字体及资源身份，冻结规范化配置、转换器与配置指纹。Renderer 不指定文件路径、资源哈希或可执行模板。新产物身份包括快照、格式、转换器及生效配置指纹；读取缓存和预览使用同一身份。已有请求不补默认字段或更改原摘要，已有转换器、ready产物、原键与恢复能力保留。新设置不覆盖旧产物；旧待定请求仍绑定原配置，字体资源变化时明确拒绝重建，不能偷偷使用新配置生成旧身份文件。

PDF/DOCX消费同一基本样式配置，单位转换分别归原渲染适配器；不承诺两格式相同分页。页眉页脚只接受有界纯文本及受控页码占位，不执行用户HTML/脚本/模板。页眉页脚存在时预留最小页边距。实际字体/纸张和模板支持以锁定版本与同包样本验证，未验证字体不作为可选项开放。

PDF仍沿隔离、禁网、保留Electron沙箱的printToPDF。先生成、验证、持久化ready，再把该固定文件交现有PDF.js预览；另存复制相同exportId/字节hash，不重新排版。不将预览ready等同另存或发送。取消、迟到、错误、unknown及刷新失败保留原请求、旧文件和正文，不换键重提。没有Team、分页内核、云转换、第二正文或新Runtime。

## 实施检查点、兼容与回退

先验证配置合同与唯一偏好持久化，不提前向用户开放未连接的设置。随后独立接通配置冻结/产物身份和必要迁移，最后接共享渲染、PDF预览和另存。每步准确diff与独立复核；最终同SHA完整门禁、固定样本及原生入口验收。迁移只加性保留旧数据，旧ready文件、正文与原件不可重写；撤销新入口仍保留新增格式的读取能力，不能将旧二进制直接打开已升级真实库当作回退。

必要验证：旧请求摘要/回执重放、并发/失败事务、日历与个人草稿隔离、保存重启；同快照两套配置产生不同产物且旧hash不变；原请求重放不重复生成；字体变化、取消、磁盘/重名与迟到保全；PDF预览和另存源目标hash一致。源码和工程测试不代替律师业务接收，系统IME/真实Provider另记。只在合成数据执行，不读写真实凭据。

## 冻结身份的实施约束

新加配置化转换器docx-v2/PDF-v3，原docx-v1/PDF-v1/v2仍接受旧请求、原意图与回执。只有明确带样式的新请求使用宿主资源解析端口；未接入该端口时拒绝配置导出，不偷偷使用旧渲染。产物配置包含样式、可信字体家族/文件SHA256和配置指纹；存储重算指纹，SQL列与JSON身份一致，ready后继续原不可变触发器。新唯一键加配置指纹，查询按有效配置取当前产物，同时允许只读查看最多20份旧产物。旧请求不补样式，不改变原摘要；重放已ready文件不生成，pending字体资源变化明确拒绝，不替换旧身份。

0022仅为delivery_exports追加两个配置列并扩展原唯一索引；旧ready行自动得到NULL配置和空指纹，旧文件/原快照/意图/回执不变。遵循ADR029维护入口：原25份SQL/tag/when/hash逐项保持，只在冻结manifest/journal末尾追加经批准的新项并更新marker摘要，不修改桥接算法。真实旧25项库、原A/B各前缀均回归；新索引创建失败要证明本次DDL/记录回滚，重开能正常升级。不能为新字段放宽未知迁移拒绝。

公开接口参考：[Electron printToPDF](https://www.electronjs.org/docs/latest/api/web-contents#contentsprinttopdfoptions)。实际参数与docx本地类型/现有渲染代码逐项核验，不因最新版文档存在引入新依赖。

配置化PDF将通过宿主白名单读取并复核SHA256的字体字节纳入本次隔离打印，不再按local同名字体查找；字体只存在于临时打印内存，不复制进安装包或工作区。当前仅开放待同包验证的单face Arial Unicode MS。苹方系统TTC包含多face，精确SC face尚未验证，因此界面暂不提供；合同保留枚举但宿主拒绝未验证资源，不能静默选择HK等其他face。DOCX继续引用同一家族名称，未嵌入字体，不承诺跨机器排版一致。偏好未读到时不得按默认值启动新导出，读取失败提供原入口重读，不锁住页面导航。

字体通过本次独占隔离Session的protocol.handle拦截两个精确HTTPS形状地址（document/font），直接返回内存HTML/已核字体Response；其他URL/方法拒绝，绝无net.fetch或网络回退，也不注册全局协议/监听端口。此做法避免23MB字体扩为31MB data导航URL触及Chromium IPC限制。script/connect仍禁用，font-src仅此固定虚拟origin；结束后撤销handler并销毁打印窗口。旧无配置PDF-v1/v2路径保持原行为。

配置化PDF打印前读取可信单face字体的Unicode cmap（4/12）验证本次实际字符集；未覆盖的稀有字、表情或符号明确拒绝并保全正文/快照，不允许浏览器悄悄fallback到未冻结资源。此为保守失败边界，不承诺覆盖所有姓名；后续扩大字库须独立验证资源、预算与退出方式。普通正文编辑和现有Word出口不因此禁用。跨平台单元夹具验证cmap边界；真实字体/中文/长表格/页眉页脚必须由同包原生样本验收，不用条件跳过单元门禁代替。

同包试验发现页眉页脚模板引用外部font-face会触发Electron“Printing failed”，因此运行模板保留公开headerTemplate/footerTemplate，仅引用白名单家族名（与DOCX一致），正文仍由私有Session提供实际已核字体。真实合成5页输出已逐页查到页眉、页脚及页码，PDF字体表为ArialUnicodeMS，仍不宣称模板跨机器的二进制字库嵌入保真。原失败、调整和文件检查证据保留；不得为通过关闭沙箱、CSP、网络白名单或改用云转换。
