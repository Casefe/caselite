## 问题与批准

当前 Yjs 13.6.33 在撤销删除后，恢复出的插入片段被新编辑再次分裂时，撤销原插入可能残留文字。固定合成正文“甲乙丙丁”经插入“履约条款”、删除“乙履约条款”、撤销删除、在恢复片段中插入“补充”、逐次撤销后，原版残留“甲乙条款丙丁”。实际 Body 和 Task 消费者、原包 ESM/CJS 均已复现；原生保存后重开保留同一错误由主控另行留证。

用户批准固定 PR836 的 MIT 两文件回补与完整验证，不以本文替代许可准入或产品验收。不升级 Yjs 主版本，不以改变捕获时间、重建历史或推断用户意图规避该问题。

## 决定与不变量

在同一 Yjs 13 编码和 API 下，按恢复片段的实际跨度处理原插入的撤销边界，并保留既有 origin、scope 和 deleteFilter 检查。上游固定源文件未经再次改写；ESM/CJS 分别重建，不能只改 `src` 而继续运行旧 bundle。

维持现有唯一 Yjs/Document Owner、SQLite 事务与类型化应用入口，不增加同步或正文系统。旧修订和旧快照按其原内容读取，已错误保存的文字不会自动修正。修复不变更正文格式号、数据库迁移、IPC、权限或交付快照身份。

## 验证与剩余准入

仓外固定 bb745 快照中，未修改版本的 88 个生成文件与官方 npm 包逐字节一致。候选仅改变批准的九文件，实际包导出的 Body/Task 原 P1、相邻文字、防过删、批注、表格、emoji、旧四修订及新旧解码已实测；原失败日志保留。ESM 与 CJS 在分别独立的模块图验证，不要求两图中的类构造器相等。

这些结果证明候选算法与包产物的有限兼容性；不代替主控在当前集成 HEAD 上的适用检查、实际 Electron 撤销/保存/正常退出/重开、旧修订、同快照 Word/PDF、中文输入及业务验收。全部历史 PR 的逐文件研究仍按真实覆盖范围记录。

## 回退与维护

由主控串行移除该补丁登记、对应锁身份及发布资源接线，重新装配官方 13.6.33 并验证实际 resolver。按本地独立提交回退，不重置其他 Owner 的 WIP，不回退/覆盖用户保存的正文、旧版本或快照。回退会恢复已知原 P1，必须明确报告。待上游正式修复后，以同一回归集比较再替换，不能仅凭版本号或 PR 状态移除保护。
