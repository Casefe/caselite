# CaseLite｜LLM代码保护与受控变更守则

> 本规范适用于开发、修复、重构、升级及审查中的所有LLM，人工开发采用相同风险判定。需求与接收Owner为谭辉，工程规则Owner沿DEV-1562，规范批准与接入归[DEV-1935](https://linear.app/logixy-ai/issue/DEV-1935)。服从[AGENTS](../AGENTS.md)、[现行01—06](./SOURCES.md#2-六份现行-resources按任务读取)及本轮批准；不授予Git、外发、费用、数据删除或发布权限，不恢复旧队列。
>
> 本文规定必须执行的工程责任及后续机制验收合同。规则存在不证明宿主隔离或自动保护已实现；代码索引、自动保护清单与本规则的专门机械接入尚未实现，记`NOT_RUN`。实际检查及独立回归沿既有入口，新增/修改本文额外绑定准确Diff和SHA-256，见第九节。

## 一、稳定内核与受控扩展

CaseLite以已准入成熟技术栈、开源组件和既有架构为基础，优先通过公开接口、配置、扩展点及既有Application/Port实现获准需求。每次变更保持核心契约、数据权威、安全、交互和恢复能力，作最小而完整的修改。

保护按职责、影响和稳定契约确定，不按作者、行数或目录名确定。LLM编写的胶水也可能承担权限、事务或保存确认，须同样保护。保护允许有证据的漏洞修复、依赖升级和架构纠错，不得借保护长期保留已知缺陷，也不以开源来源当作正确性证明。

## 二、资产保护与变更动作

### 2.1 保护分级与裁决

| 资产等级 | 典型对象 | 修改要求 |
| --- | --- | --- |
| 核心保护 | 核心框架内部、进程/权限、数据权威、格式/迁移/恢复、密钥及构建发布信任链、门禁 | 普通任务不改内部契约；必要修改须明确范围、兼容/恢复分析及独立技术复核，长寿命决定按ADR/必要Spike |
| 稳定组件保护 | 已准入验收组件、公共API、共享UI骨架、领域表单、交互和设计令牌 | 优先公开扩展点；内部修复核对Owner、消费者行为类别与未知项，并回归及独审 |
| 业务受控修改 | 领域业务、页面展示、外围适配和编排 | 获准Issue与文件内修改，保持上级契约；按实际语义提高保护等级 |
| 实验隔离 | 获准Spike、合成夹具和临时原型 | 明确目录及数据隔离；不自动接入产品，接合重新准入/验证 |

现行合同、AGENTS及经有权Owner批准的保护规则/清单形成最低保护要求；多项职责取要求并集，冲突按现行来源/授权规则从严核对。索引只展示批准，不自行产生授权效力；未登记、解析失败、无静态引用或改名移动均不解除保护。清单未实现时沿原Issue记录判定，不要求先人工补全全仓。

作者可提高、不能自行降低保护等级。改变权限判定、事务边界、保存确认、持久化格式、数据权威或恢复语义，均按核心保护；同文件内已证明不影响这些语义的文案不机械触发整项核心回归。新业务代码一旦承担共享/核心职责立即适用相应保护。

作者记录初判和依据，独审核对。争议、降级或例外由实时Issue/合同中有相应权限的模块Owner决定，规则/安全另核工程或安全责任；作者不能代签。原Issue记录批准人及权限依据、资产/动作、理由、不变量、候选范围、有效阶段和失效条件。上位安全、原件、许可及用户授权底线不可通过例外突破，Owner签字不能替代隔离、兼容或恢复证据；需改变上位约束则停止相关工作并按现行权限升级。

未明确的高风险先核实或缩小变更；已获准且证据充分的普通步骤持续执行，不重复请示。批准可覆盖明确后续范围，最终检查仍绑定准确候选；超范围或契约改变重新核对。

### 2.2 两维判定与适用检查

| 变更动作 | 最低判定与验证 |
| --- | --- |
| 文案/局部展示 | 证明无事件、状态、契约、可访问名称、保存/法律含义变化；局部展示及适用静态检查，仍保留资产范围/独审要求 |
| 事件/状态/生命周期 | 按行为类别回归输入、焦点、取消/重开及消费者；涉及核心触发语义则升级，CSS或接口签名未变不构成豁免 |
| 公共接口/权限/持久化/恢复 | 契约双方、负向安全、兼容、故障与恢复；长寿命决定按ADR/Spike |
| 规则/清单/检查器/模型或权限 | 精准Diff、独立批准及既有真实正负回归；不套用普通文案豁免 |

写明适用与不适用理由，不按路径/行数降级，也不把矩阵扩为所有变更全套测试。未知风险不得以模型自评代替判断。

## 三、六类代码修改的基本准则

### 3.1 核心技术栈

不直接修改`node_modules`或安装缓存作为正式修复，不擅自替换编辑器、数据库/ORM、Runtime、状态权威、打包器或同步方案，不另建第二套同职责系统。优先既有能力→公开配置/扩展点→现有适配→经准入上游修复→最后考虑受控补丁，不为绕过缺陷无限增加包装。

升级、降级、移除、替换、补丁及锁文件变化均需审查直接/传递、Peer/可选依赖、安装脚本、平台与原生ABI。获准补丁记录上游仓库/版本/commit、许可、准确差异、必要性、测试、Owner和退出条件，不静默长期分叉。生成产物通过修改获准生成源/配置重建并检查差异，不手改产物掩盖源头问题，不随意重写已应用迁移历史。

### 3.2 完整迁移组件

完整须有功能合同和验收证据，目录复制或页面能打开不证明完整。保留来源/版本、许可/NOTICE、迁入基线、适配部分、公共接口、消费者、差异、验证及维护责任。架构参考与复制源码分别处理；新增源码复用按[ADR-005](./adr/ADR-005-third-party-code-license-and-clean-room.md)先取得人工确认。

业务定制优先props、事件、配置、插槽及公开插件接口；必要封装只承担明确适配。禁止为新页面复制整套组件、裁剪不了解的分支或改状态机掩盖调用方错误。内部缺陷先定位根因/最小复现，必要时补特征测试并回归；特征测试不把已确认错误永久固化，来源/行为不清标待核实。

### 3.3 结构化UI与骨架

保护应用壳、导航、路由/工作区、布局/缩放、焦点/键盘、中文输入、设计令牌、共享表单、附件及加载/错误/保存状态。页面任务优先内容、绑定及扩展点，不顺手重写骨架、另建主题、全局CSS覆盖无关页或重做同对象表单。DOM、key、卸载/隐藏与CSS也可能影响草稿、焦点和性能，按影响验证；纯局部文案不机械要求全套桌面回归。

共享修改单写入。按本次契约划分只读/编辑、独立/共享状态、持久化/临时、平台/动态入口等消费者行为类别，记录代表样本共同契约、差异与等价覆盖依据；组件名或外观相同不足以证明等价。

未知消费者记录搜索范围、动态/平台/构建入口、剩余不确定性及后果。可能影响权限、数据、保存或恢复时阻断相关交付，直至查明或有边界/运行/契约证据排除影响或证实隔离；披露和Owner签字不能替代证据。仅已证明局限展示的剩余风险可由有权Owner限定接受。待接合候选核对已批准契约，不能判断保留阻断，不因此恢复旧队列。

### 3.4 其他保护资产

保护SQLite结构/事务/幂等/迁移，Yjs权威正文，AssetVersion/SourceVersion、Anchor及固定交付快照，原件和旧快照不可覆盖，投影不可成第二真源。保护Renderer/Preload/Main、IPC校验/权限、密钥/脱敏/CSP/Fuses及受控外发，Agent/MCP同样经Application，不直达Repository。

保护保存确认、备份/重试/未知回执、恢复和必要审计，低频或无UI不是删除依据。公共类型/API/IPC/持久化字段变更核对读写双方与旧数据。测试、CI、检查器、AGENTS、Skills、模型/权限、许可/NOTICE、ADR及验收证据也是保护资产，不得改规则自我放行。

保护真实材料、未提交/未跟踪文件、其他作者WIP及在途操作，不批量reset/clean或整文件覆盖。测试可因获准需求/缺陷调整，须说明旧保证与替代保护；不得靠删断言、跳过失败、统一更新快照或放宽阈值制造绿色。

### 3.5 业务、外围与胶水

在获准用户结果、文件与语义内，检索已有实现并最小修改；不顺手换栈、改名、全仓格式化或跨模块重构，不无限增加兼容层/缓存/开关/重复状态。外围命名不豁免权限、事务或保存语义。同一对象多入口复用其领域表单，字段/校验/权限/事务/持久化归Application，不强合为通用CRUD。

### 3.6 修改与验证闭环

确认有效基线→最小实施→受影响验证→准确最终候选回归→适用恢复演练→独审。返修重验受影响项，不用机械重跑次数证明质量。失败先区分产品、测试、环境和依赖原因，不隐藏失败、重置数据或降门禁；未变化且仍适用的证据可复用。不稳定/时序问题明确运行条件并保留所有失败。

## 四、源码范围与执行副作用

沿[WORKFLOW](./WORKFLOW.md)及原Issue的现有范围字段，记录用户结果、Owner、允许文件、资产等级/动作、非目标、消费者、验证和回退；核对实际HEAD/分支/WIP、依赖和单写/执行槽，不建平行账本。保存编辑前状态与未跟踪文件，未知变更先辨认。

编辑源码不自动授权启动默认profile、写真实库、重建依赖或联网安装脚本。有副作用执行明确实际命令及继承授权、可写数据/profile、生成/构建/缓存、GUI/迁移、网络/安装脚本范围；只读或未变范围可复用有效记录，不逐命令另填表。

首次写入/迁移前核对配置、环境/默认值、规范化路径与符号链接等实际目标，不凭临时目录名证明隔离。真实用户目录、默认profile或未知目录不能用于无明确授权的测试写入；入口无法证明执行前拒绝误指向时，不运行可能写入命令，改用已验证隔离夹具/副本或报告阻断。常规回归优先合成数据，副本仍须保护隐私。

Node/依赖/ABI/Build/缓存共享写入沿单槽串行；缓存核对键/来源匹配，不全量盲清，无法确认时仅在有权范围隔离/重建对应产物，不动他人工作。未知启动/迁移/安装回执先查进程、日志及落盘，保全现场，不盲重试、强杀或清目录。GUI及测试默认静默，遵循既有批次授权。

## 五、最终候选、执行输入与证据

baseline SHA不能代表混合工作树。候选绑定实际Diff、未跟踪清单/hash、适用依赖/锁文件/ABI、生成输入、构建/测试配置、规则/工具及环境非敏感标识；哈希不证明安全或审批身份。

最终验证使用运行期间稳定的准确输入，可采用只读候选副本/快照或已验证的等效控制，不要求每小改新worktree。沿原目录执行须有可核查停写交接与执行控制；普通单写声明或前后哈希不足以单独证明。相关动态资源纳入输入，输出范围防止反写输入；缓存/共享产物须匹配候选，不能确认则在有权范围隔离/重建。

授权范围与准确候选检查对应；审查、测试、回归绑定同一候选，打包运行另绑定实际产物hash及构建输入。输入变化使受影响结论失效；A→B→A前后哈希相同不能冒充执行全程A。不能证明稳定则保留有限证据，阻断准确最终候选通过结论，不凭人工估计补保证。

## 六、可判定验证与恢复

每项适用验收记录输入/前置版本、实际入口、操作/故障点、可观察预期、禁止结果、证据与候选；可说明不适用理由，不只写“做了集成/恢复测试”。覆盖率、截图、退出码不单独证明数据正确。缺陷回归优先证明原候选失败、修复通过；原候选无法安全可靠执行时，用保全失败证据或隔离等效复现，由独审核对判别能力，不凭修复后通过推断。已有测试充分时复用，不机械加测；非缺陷修改无需制造旧版本失败。

| 变更 | 针对性证据 | 不能替代 |
| --- | --- | --- |
| 页面/共享UI与组件 | 需求行为、失败及适用消费者/输入/焦点/取消重开/布局 | 只截图、只断言实现或单页通过 |
| Application/IPC/胶水 | 输入负测、权限、取消、重复提交、未知回执与真实边界集成 | 全mock成功返回 |
| 数据/正文/迁移/恢复 | 合成旧数据、写入故障、重启及下表适用断言 | 新空库或重置后成功 |
| 依赖/核心栈/构建 | 来源/许可、兼容/安全、安装/打包及目标运行 | 类型检查或另一平台CI |
| 规则/Skill/检查器/权限 | 既有独立新上下文真实正负回归与有效回执 | 文件存在或quick通过 |

| 适用对象/故障 | 必须观察到的状态；禁止结果 |
| --- | --- |
| 保存失败/重启 | 已确认修订正文及必要元数据重开一致；未确认写入按合同保全或明确失败，禁止已确认内容静默丢失或旧投影冒充新正文 |
| SQLite事务/幂等 | 中断满足既定原子性，重试无重复对象/必要副作用；禁止不被合同允许的元数据/正文/幂等/必要Activity半提交 |
| 跨介质恢复 | 适用结构化记录、Yjs、AssetVersion/SourceVersion文件及关联可解析，原件/旧快照hash保持；禁止仅SQLite完整而正文/文件缺失、错关联或原件被覆盖 |
| Anchor/交付 | 固定来源版本与交付修订正确；失配/不兼容明确报错，不静默跳错版本或以投影改变原事实 |
| 损坏/迁移/版本不兼容 | 按支持范围验证旧数据/升级/恢复，明确报错并保留现场；禁止静默新空库、重置报成功或旧程序误写新库 |

只验证本次可能影响的对象和已准入能力，并说明选择依据，不提前建同步等能力、不机械全产品灾难演练。恢复记录合成数据/版本、故障时点、前后适用值/非敏感指纹、关联及用户结果；数据损失窗口或支持范围变化事前明确决定，验收时不能临时降低已确认保存保证。

命令以[DEVELOPMENT](./DEVELOPMENT.md)与当前package.json核实：`pnpm check:quick`、`pnpm review:changes`，按影响补`pnpm test:integration`、`pnpm run ci`或`pnpm test:full`。桌面边界、公开资料、日志或依赖至少`pnpm security:baseline`，联网漏洞审计单记；Linux CI不替代真实Electron。规则/Skill、模型/权限、检查器变化或同类错误复发执行[既有独立回归](./REVIEW_HANDOFF_EXERCISE.md)，并运行`pnpm review:changes --require-regression <本轮回归JSON>`；不得以固定Node子检查冒称pnpm完整入口通过。

## 七、分别制定代码、环境与数据恢复

| 类型 | 必须具备 | 限制 |
| --- | --- | --- |
| 代码 | 编辑前快照、准确基线/本轮差异、未跟踪文件及后续变更核对 | 仅撤本轮，不凭HEAD批量覆盖混合WIP |
| 依赖/环境 | 原版本/锁文件/补丁/构建配置及可重建或可用产物证据 | 旧源码不保证旧依赖可得，ABI和产物须验证 |
| 数据 | 一致性备份、版本兼容、恢复演练、正文/原件/关联及迁移后新数据方案 | 旧程序不保证兼容新库，旧备份覆盖可丢新增数据 |

运行中复制SQLite主文件不能默认当作完整备份；使用可靠一致性方法，恢复前核最近写入并保留现场，有损/不可逆操作另获授权。优先兼容演进，不能安全降级则明确只能前向修复及隔离路径，不假称可回滚。功能开关只能限制新行为暴露，不能恢复损坏数据或替代权限。

## 八、审查、交付与状态

另一独立Sol High按[CODE_REVIEW](./CODE_REVIEW.md)核对实际需求、准确Diff、裁决、消费者、测试有效性、副作用、稳定输入、失败和恢复，必要专业复核按风险执行，实质返修重核受影响项。完成须满足获准结果、不变量、未知影响放行条件、适用真实检查/恢复及必要独审，无未处置阻断；工程、GUI、律师接收各自记录。

沿原Issue/既有模板记录合同修订/批准、Owner/等级/动作、SHA与快照、消费者、来源/许可、命令/退出码/证据、失败恢复、独审、未测/风险、回退、Git状态及实际模型/可得成本；未知如实记未知。Git、外发、费用、发布及状态推进仍按当次授权。

`PASS_REAL / MOCK_ONLY / NOT_RUN / BLOCKED / FAIL`必须说明对象、数据类型和覆盖。合成数据经真实SQLite/Yjs/文件/恢复入口满足断言可记限定范围`PASS_REAL`，不代表客户数据/全量验收；替身模拟关键机制才记`MOCK_ONLY`。方案审查、规则接入和保护器实跑分别验收，不相互代替。

## 九、规则权威、自动机制与后续验收

保护规则/清单、检查器、CI和Skills本身独立审查。检测依据可信基线或独立受控配置，不能只信候选自改规则/自造通过JSON，不能删除匹配规则给自己豁免。确有权限更新也须独立批准与负向验证；哈希不证明批准人身份。

Skills指导判断，差异检查/CI检测并阻断交付，宿主权限/执行器策略限制实际写入，三者不能混称。模型若可任意shell写全盘，提示词、只读注释或本地hook不证明不可绕过；缺少权限隔离如实说明。远端CODEOWNERS结合保护/必需审批只约束相应合并，不阻止本地编辑，也不强制当前原型改用PR。

沿现有检查器/索引方案扩展，批准等级由规则/Issue拥有，索引只派生；新增文件、改名/移动/删除、依赖/配置间接改行为及旁路实现不得解除保护。另有明确授权时才可封装精简Skill，引用唯一规则、不复制全文；不因规范列名安装Skill、依赖、新Runner或宿主权限系统。

当前`scripts/check-quality-changes.mjs`规则指纹与保护列表尚未直接覆盖`docs/CODE_PROTECTION.md`和`docs/CODE_HYGIENE.md`。引用变化可能触发现有回归，但`rulesSha256`不证明这两份正文版本。新增或单独修改时额外保存各文件SHA-256、准确Diff及候选快照并独审，照常完成既有独立回归和带回执检查；不得以机械未触发免除。机械接入需另有获准Issue及负向回归，不据文档存在宣称自动保护已覆盖。

以下为后续机制实现的验收合同，当前自动机制与这些专门夹具为`NOT_RUN`；人工/代理开发现在仍须执行相应责任。机制实现须另获准，复用既有回归而不新建质量运行器。

| 场景 | 必须观察到的结果 |
| --- | --- |
| R1 核心保存适配器被作者/索引降成胶水，另有合法范围批准 | 自降/无权/突破上位底线拒绝；索引不能覆盖权威；合法批准只在范围内有效且依据可核对 |
| R2 共享保存变化动态消费者未知；另有只读隔离证据 | 未排除核心影响阻断；有效证据限定排除/隔离后可继续；披露/签字不代替证据，代表样本等价依据可核对 |
| R3 测试期间A→B→A、配置/缓存/产物替换；另有准确冻结候选 | 越界写被拒绝或最终结论失效，旧证据/错产物不能归属；合法候选及实跑产物身份对应 |
| R4 profile经默认值/配置/链接指向合成“真实数据哨兵”，另有独立合法profile及未知回执 | 误指向首次写/迁移前拒绝，哨兵清单/字节不变；合法目标能执行；未知回执先核查，不盲重试/删除，不以真用户目录演练 |
| R5 原缺陷/等效复现、保存崩溃及缺正文/版本文件/错Anchor关联备份 | 回归识别旧缺陷且修复通过；缺失/错误判失败或不兼容，不只因启动成功报恢复通过；适用修订/原件/关联满足第六节 |
| R6 同一组件合法纯文案、卸载修改及一行保存确认变化 | 文案适用局部检查并保留资产审查；生命周期做相关消费者回归；保存按核心；不按行数/路径降级，不机械阻断合法低风险 |
| 其他绕过与恢复 | 受保护文件移动、Application旁路、删测/弱化CI、改清单自放行、陈旧回执被识别；混合WIP只撤本轮，旧程序不兼容新库拒绝假回退 |

每项留输入/候选、操作/故障、预期/实际、退出码与原始证据；不具备条件记`BLOCKED/NOT_RUN`。夹具通过仅证明实际覆盖，不证明全仓语义识别或宿主不可绕过。代码精简与索引职责继续归[CODE_HYGIENE](./CODE_HYGIENE.md)，不因保护规范建立第二真源。
