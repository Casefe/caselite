# DEV-1554｜一个Task内的辅助起草与人工路径

依据现行04、已接受代表任务及DEV-1554当前范围。这里只定稿用户流程；不是材料导入、真实Provider或候选另存已实现的证据。实现顺序消费1579来源、1580输入／Run合同，由1651选材、1652唯一Runtime、1653 Run、1655新稿、1657全流程分别接线。

## 代表任务与入口

“梳理两份材料中的事实、矛盾和缺件，形成律师内部沟通初稿”。首页可以先表达目标，再转独立Task；既有Task直接继续，不因多次运行或加入项目重建。项目归组不改变Task ID、来源、正文或自动授予材料范围。内部沟通稿不是已核实事实、专业审查或正式法律意见。

## 不使用Key的完整人工路径

创建Task／填写目标→在已支持范围内选择和阅读材料→人工记录事实／矛盾／缺件与来源→编辑成果正文→核对→显式保存→退出／重开同一修订→在导出消费者就绪后选定同一快照并实际打开Word或PDF。没有Key不弹出强制模型配置，不创建WorkRun，不阻断正文。保存与交付分别显示，不以“已有正文”假装文件已导出。

当前人工Task／正文与目录可运行；受管PDF、Anchor、OCR及双格式尚须原消费者接线。扫描件必须显示识别中／失败／候选待核对，本变体在1649未通过前不能声称完整人工材料链完成。

## BYOK辅助路径

1. 用户在Task内明确选择本次材料／摘录及目标；可选择已保存且有权访问的历史版本。原句、OCR候选、个人备注、用户更正和历史候选逐项标明角色，失败partial、被更正旧内容、其他Task和未选材料默认排除。
2. 发送预览显示Provider／模型、确切文字及稳定来源／修订、排除项、预算和费用未知提示。Key在设置中保存与删除，预览不展示Key。没有可发送内容、权限／来源已变化、无Key或模型不可用时禁止开始并保留输入；用户可转人工路径。
3. 用户确认这份预览后，以固定Run ID和Manifest执行。每Run一个Provider、一个Pi Loop、一次实际派发，不自动路由、重试收费请求、补读全库或隐形发送完整历史。预览后内容、模型或版本变化须重新预览确认。
4. 流式候选明确“待核对”；可Stop，取消／网络中断／401／429／额度或超时保留可得partial及错误。停止不保证远端取消或零费用；结果未知先核对原Run，不自动新建Run重放。切Task后迟到事件只归原Run，重启不自动续费。
5. 用户核对事实／推断／矛盾／缺件，来源需分别检验可访问、定位正确、原文是否支持；模型自称已核验、引用ID或链接都不是证据。缺材料明确报缺，不填补成已查明。
6. 用户选择拒绝或接受为新Document。拒绝仅记录候选决定，不写原件、原稿或现有Document。接受使用稳定业务幂等键，经Application调用公共Document保存新稿，保留Task／Run／Manifest与固定SourceRef关系；只在真实落盘确认后显示新稿已保存。接受回执未知先查询同键，不重建第二份。
7. 新稿可以人工修改、保存、重开。接受新稿不等于正式定稿／导出／外发／完成Task；1701确认及同快照双格式分别接收。当前一个Task一个成果的旧约束必须由1655消费卡在原Owner下增量迁移，不能用覆盖现稿冒充新稿。

## 状态与界面责任

| 状态 | 用户看到的内容／可行动作 | 不允许的暗示 |
| --- | --- | --- |
| 未配置／无可发送输入 | 设置模型或人工编辑，输入保留 | 强制登录或Key才能工作 |
| 预览待确认 | 确切payload、来源修订、Provider和预算 | 用UI勾选代替宿主授权 |
| 运行中 | 当前Task／Run、流内容、Stop | 另一个Task显示或提交此候选 |
| 取消／失败／中断 | partial、已知错误、远端／费用未知，查询原Run | 自动付费重试或假称撤销远端 |
| 候选待核对 | 原文对照、拒绝／接受为新稿 | 模型成功就是正文已保存 |
| 接受提交中／未知 | 原幂等键查询、输入和旧稿保全 | 新键反复保存或覆盖旧稿 |
| 新稿已保存 | 新Document身份与已确认正文修订，可重开 | 已正式确认、已送达或Task自动完成 |

Task对话由1699唯一拥有；1650／assistant-ui只投影；1653拥有Run，Pi内部session不是另一个业务历史。D01/D02保存正文；来源由S12解析，UI不抓Editor DOM冒充已保存原文。

## 实施与验收计划

当前只支持显式输入文本的运行适配器可以复用，不冒称材料已自动读取。先把1580的Manifest接到1651／1654受控读取，再验证1652真实请求，随后1655新Document事务；中间增量各自演示。每项保持现有对象身份、恢复与人工确认责任。

最少正例：固定合成两份材料经真实用户Key，确认输入→生成内部初稿→拒绝无写入；另一次接受新Document→修改保存→退出重开，原稿与原件hash不变。真实Key和费用须用户实际提供／确认，不从私密配置中寻找，也不改用另一收费Provider。无Key人工路径独立跑通。

反例：401／429、无Key、输入或Provider在预览后变化、未选／跨Task、材料注入要求越权、未知工具、取消后迟到／重复事件、输出引用不在实际Manifest、接受重复／旧版本／回执丢失、存储失败及重启。流式输出、已保存Run、新稿保存和导出分别记证据，MOCK_ONLY不能替代真实Provider。

产品操作／法律质量、真实外发与费用及最终UI体验仍需相应人工接收。本设计未执行真实Provider请求，未启用材料读取或候选写入；回退只撤回说明，无用户数据操作。不引入专业事实平台、多Agent、Shell、外部MCP或后台持续行动。
