## 目标用户及定位

CaseLite 首先服务独立律师和小型法律团队，成为律师开始、组织、持续处理法律事项（Matter）的个人工作工具，并在需求成立时支持对象级协作。优先支持诉讼、合同及合规工作的共同基础：来源材料、专业判断、任务、交付和知识复用。

产品路径：个人本地优先、无需注册的基本工作 → BYOK AI 辅助 → 事项/文档协作 → MCP 连接外部来源与应用。核心个人功能以免费为目标；不承诺尚未验证的成本比例和服务能力。

## 第一版用户可见不变量

1. **Matter 五栏目**：概况、任务、文件、交付物、动态；“审查 Review”是上下文视图，而不是新增第六栏目。
2. **原文可信链**：文档原件、来源版本、原文 Anchor、事实/规则/争点、支持/反对/不足、候选 Finding、律师 Decision、交付版本和经确认的可复用知识彼此有关联；引用可定位不代表论证必然成立。
3. **用户控制结果**：AI 的结论首先是可供复核的候选；正式法律意见、交付和知识复用必须经过律师确认。
4. **本地工作不依赖在线服务**：断网仍可进行已支持的人工功能；关闭 AI、协作或 MCP 不应令已有本地资料无法使用。
5. **协作可见性准确**：本地已保存、服务器已接受、远端同步、法律已审核是不同状态，不可混同。Matter 分享与单文档/任务链接授权不能互相错误扩大。
6. **数据外发透明**：用户自己的 Key 调用所选 LLM/OCR 服务前，应明确实际发送范围、状态和相关成本；不默认全库上传。

## 当前开发范围与非目标

| 能力归属 | 要验证的最小用户结果 | 当前边界 |
| --- | --- | --- |
| P0 工程基线 | 一名非专业程序员能让新 LLM 在干净环境安全开发与验收 | 不实现正式 Matter/BYOK/共享/MCP 功能 |
| P1 本地工作 | 新建 Matter、关联原件、PDF 原文锚点、保存与重启恢复 | 不把原件路径当身份，不自动改写历史正式结论 |
| P2 本地智能 | 一个 LLM＋一个 OCR Provider＋一个受限 WorkRun 产生带依据候选 | 无自动正式交付，无云端代理/多 Agent 前提 |
| P3 共享协作 | 两客户端共享授权对象并可靠同步结构化数据、富文本、附件 | 服务器不承担 BYOK 推理；Redis 非持久化真源 |
| P4 外部拓展 | 一个真实知识来源与一个外部 MCP 客户端，受控候选写回 | 不建第二数据库/权限系统/Runtime |

当前不规划成第一版前提：完整 CRM、财务/支付、企业 OA、插件市场、通用工作流搭建器、复杂组织权限体系和全部外部连接器。
