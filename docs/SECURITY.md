# CaseLite｜开发与数据安全约定

- **性质**：安全设计与公开仓库最低要求。它不是正式安全审计，也不能替代代码级验证。
- **来源**：[Linear v2.2 架构](https://linear.app/logixy-ai/document/caselite架构与开发约定-v22现行-d22d41990c7d)、[DEV-1561](https://linear.app/logixy-ai/issue/DEV-1561)
- **适用位置**：公开 GitHub 仓库 `Casefe/caselite` 及开发机 CASDEV 工作区。

## 1. Public 仓库红线

严禁 Git commit、push、PR、附件或 issue 上传：

- 真实案件文书、客户合同、身份证件、账户信息、私人通讯和未经授权的法律资料；
- API Key、SSH 私钥、Token、登录凭证、数据库连接秘密、真实 `.env` 文件；
- 含秘密或真实法律资料的 SQLite 数据、备份、日志、错误堆栈、截图或构建包；
- 许可证未明确允许复用的竞品、商业版、AGPL/其他附特殊义务的源码（未评估前不得复制）。

`README.md`、合成测试样本和公开设计摘要可以发布，但公开性应由使用者确认。`.gitignore` **不是秘密防泄露保证**，已提交到 Git 历史的秘密不会自动消失。实际工程需设置可运行的 secret 扫描、依赖审计及提交前/CI 门禁。**不要在此文件记录任何真实密钥。**

## 2. Electron 边界（待编码验证）

- Renderer 设置 `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`，禁止不受信任网页获得 Node 权限。
- Preload 仅暴露最小白名单、类型化 API；IPC 校验调用者、对象范围、参数、权限、版本和错误，不能暴露任意 SQL、命令、URL 或文件操作。
- 对外部导航、窗口创建、CSP、文件读取和自定义协议采取明确安全默认值；恶意 PDF/网页和工具返回视为不可信数据。
- `safeStorage` / 系统凭据保存 BYOK Key 的方案需实际 Spike；密钥不进入普通业务数据库、日志、同步、提示词记录和公开文档。

## 3. 外发、费用与授权

- 调用 LLM、OCR、外部知识源或 MCP 前，应显示发送内容的来源与范围、目标 Provider、估算费用、取消和失败恢复；不得默认上传全部 Matter/资料。
- Skill、模型和外部文档不能通过提示词提升权限；高风险写入与法律正式交付必须经过确定性宿主权限控制和人工确认。
- 对共享 Matter、独立文档链接、附件版本维持一致的对象级权限；已下载明文副本无法被远程“收回”，不能虚假承诺。

## 4. 本地磁盘与数据恢复

CASDEV 当前为**非加密 APFS**，仅适合公开/合成研发材料；真实客户文件应存受保护、必要时加密的独立位置。运行中的 SQLite 需要使用一致性备份方式而非随意复制主库文件；共享前后均需考虑 Pending、Snapshot、附件及凭据的隔离备份。

开发脚本应验证磁盘挂载且不从 CI 依赖 Mac 上的绝对路径。清理、重建、数据库迁移、危险 Git 命令、公开发布及仓库权限变化须经过人类明确授权。

## 5. 安全测试与阻断条件

- 使用**假** Key 验证扫描器可以拦截泄露；测试越权 IPC、路径穿越、恶意链接、注入内容、意外外发与日志残留。
- 不关闭或删除测试/CI/防护来换取绿色结果；未执行的安全检查写明“未执行”。
- 违反安全边界时停止写入、保全数据并报告风险，先形成修复/回退路径再继续。

## 6. 漏洞处理与公共协作

在未确认安全报告渠道前，不在公开 Issue 发布真实凭据或客户数据；项目管理员应规划私密安全报告方式。发布正式版本前需独立安全审查。当前没有声明生产级安全认证或合规评估已经通过。
