## 1. 先采用的工作方式

保持模块化单体与现有技术栈。每张获准Issue交付一个真实用户结果，首个切片就接UI→typed IPC→Application→持久化，测试后由独立上下文核对，再交现有主控在同一准确候选接收。

沿用现行模型规则：Sol规划，Terra medium实施/最多一次返修，独立Sol High复核；高风险与重复失败交Sol High。模型不可用时保留任务并报告，不自动换名单外模型。

用户最新Git规则优先：commit、push、merge分别取得明确授权后由Sol High执行。研究和普通文档准备不授予任何一项Git操作。共享目录只有一个产品代码写入者；只读研究和独立复核可在有边界的上下文进行。

## 2. 第一批只准备三个工作包

建议顺序服从现有主控正在执行的获准任务和写入权。以下是对原卡的接收方法，不是新建三条并行开发队列。

### A. 接收已有成果，建立准确候选

原责任入口：DEV-1828调度；1829核对历史成果；1838同包接收；1904核对工程要求。

**唯一结果**：产品负责人拿到一个能启动、版本可识别、已纳入范围清楚的程序。

步骤：

1. 核对当前HEAD/dirty、在途文件Owner、仓外候选、未合PR及源码/构建/ABI/GUI写入时段。不能因chat idle、Issue状态或目录clean就假定已交接。
2. 沿原实体登记每项成果：是否已有实现、是否已进主目录、在哪个准确候选、缺哪类验证。历史通过仅在代码/规则/依赖/环境仍适用时复用。
3. 当前写入者完成或保全后，冻结一个准确源码清单、锁文件/规则指纹、工具版本和候选包hash。不要从活跃目录边复制边宣称冻结。
4. 对该候选执行受影响定向检查，并按风险补现有quick、review、integration、安全及full/原生验证。规则等触发变化时执行既有独立回归；不以本研究副本通过替代。
5. 独立上下文依据准确diff和原始结果核对。产品负责人按普通模式操作，记录工程与律师接收的各自结论。

交付包括：纳入/未纳入范围、入口、源码/包hash、正反例、未测项和回退。允许文件由该次原Issue领取时确定；本方案不授予全仓写权限。

### B. 从设置完成备份和隔离恢复

唯一实施Owner仍为DEV-1593，真实前置为1755、1579、1590；1579历史已完成仍需核适用性。由原Owner明确当前可用前置，未具备时先推进其最小必要产物。

**唯一结果**：备份后在新目录恢复，用界面重新打开同一任务、正文、原件和交付快照；当前工作区不受破坏。

实施前决定：备份清单与一致截点、正在编辑时的行为、密钥与可重建索引处理、支持版本、失败/中断恢复、RPO/RTO承诺。存储/恢复决定按原ADR和独立技术复核，不在本文默认选定新协议。

验收：

| 场景                         | 预期                                             |
| ---------------------------- | ------------------------------------------------ |
| 正常备份/恢复                | 完整清单与hash可核，GUI找回原对象/正文/来源/快照 |
| 坏包、缺件、hash错误         | 明确拒绝或隔离处理；不覆盖当前库                 |
| 路径穿越、重复身份、超大展开 | 受控拒绝，不写出隔离边界                         |
| 不支持的旧/未来版本          | 明确兼容结论；不自动清空、降级覆盖               |
| 备份时有写入                 | 数据库、正文修订和原件引用保持一致截点           |
| 中断、空间不足、权限失败     | 保留可说明的阶段，允许安全重试/清理临时产物      |
| 恢复后的许可/学习状态        | 沿1593与1878/1763的既有决定，不复活失效许可      |

如涉及第三方源码或新库，先按ADR-005/1569核准；不为了备份新建同步平台。代码回退与数据恢复分开，保留原库、原件和固定版本。

### C. 故障隔离与代表任务联合验收

原责任：1861窗口/IPC、1863 PDF隔离、1864产物安全、1865解析预算，领域卡各自接收，DEV-1657负责完整代表任务。1904核对页面恢复等缺口是否已有原Owner；没有则提交最小归属，不抢占其他功能Owner。

**唯一结果**：一项输入/运行失败不会误报成功或破坏已保存工作；同一个包完成承诺的代表任务流程。

最小流程：人工创建任务→导入固定材料→阅读/标注/摘录→编辑保存→选定输入的获准AI→候选接受/拒绝→固定快照→实际打开Word/PDF→退出重开→隔离恢复。

搜索、OCR和来源回跳等1657原承诺保留；基础切片演示可先完成，不能据此关闭完整总验收。无真实Provider授权时AI部分保留NOT_RUN，继续完成不依赖它的工作。

故障注入由执行者在隔离工作区进行：普通页面异常、renderer终止、坏/大文件、取消与迟到、保存冲突与未知ACK、坏备份。观察UI响应、原件hash、对象/修订、Run终态和恢复结果。Worker/utility process不冒充OS权限沙箱。

## 3. 后续模块实施顺序由真实依赖决定

| 模块      | 先做的可验收切片                               | 不应捆绑的扩张                       |
| --------- | ---------------------------------------------- | ------------------------------------ |
| 项目/任务 | 单对象创建、保存、重开、多入口同身份           | 一次实现所有看板/自动化/团队权限     |
| 文档      | 一个Document正文、明确回执与恢复、固定快照导出 | 在导出或UI改造中重建正文真源         |
| 日历      | 区分任务日期/日程/提醒；外部来源只读           | 未获准的双向推送、法定期限自动判断   |
| 财务      | 一份收费约定、部分回款、分配与冲回、项目投影   | 自动套用境外会计/收费规则            |
| 联系人    | 一个稳定身份、角色关联、编辑重开               | 按姓名自动合并和全库万能关系模型     |
| AI        | 明确选材、发送、Stop、中断历史、候选确认       | Shell/SQL权限、第二Runtime或自动外发 |
| 知识库    | 既有分类/标签/收藏及获准审查消费者             | 延期的完整模板/沉淀/共享自动复工     |
| 同步      | 原选型和隔离实验，逐故障模型验证               | 直接同步sqlite文件或一次重写为CRDT   |

现有1905/1906/1907共享组件治理、1797控制器分离、1798存储读取分离及1818采用研究继续复用。重构必须说明具体重复/耦合/故障、预期收益、保持的不变量和受影响消费者，不按行数阈值或“看起来更整洁”立项。

## 4. 原Issue前置短摘要模板

模板放在原Issue当前执行段；历史与独有负例保留。不要为所有远期卡机械填满，先用于当前一卡与随后2—3卡。

```text
唯一用户结果：
原Issue／业务Owner：
实际执行者／独立复核者：
当前候选：HEAD＋工作树清单hash；锁文件/规则/环境；包hash（如适用）
适用合同：稳定ID、更新时间、相关段落、当前批准
真实前置：需要的实际产物和可用性，缺少它哪项验收失败
允许文件／共享写入时段：
非目标：
数据权威／输入输出／版本和幂等：
正常、失败、取消、冲突、未知回执与重启预期：
实际验证及未测项：
回退：代码、数据、原件与快照分别说明
当前下一动作：
```

字段不明时，执行者先查询现有代码与连接来源。只有业务含义、必要权限或不可逆决定确实缺失时才请Owner决定；普通已获准实现不重复索取开工确认。

## 5. 分层检查的实际入口

先核package.json与DEVELOPMENT，再使用存在的脚本。下表是当前命令语义，后续脚本变化时更新原入口，不复制第二套执行器。

| 时点/影响                               | 检查                                                                      |
| --------------------------------------- | ------------------------------------------------------------------------- |
| 普通实现                                | 先运行最相关单元/合同/集成；适用check:quick和review:changes               |
| 共享协议/存储                           | 消费者合同、真实SQLite、旧库、事务/回执与恢复                             |
| 桌面/公开资料/日志/依赖                 | 至少security:baseline；联网审计单列                                       |
| 规则/模型/权限/检查器变化或同类错误复发 | 既有REVIEW_HANDOFF_EXERCISE；review:changes --require-regression 本轮JSON |
| 准确候选工程接收                        | 按风险ci/full；原生打包与普通模式场景分别记录                             |
| 产品/律师接收                           | 同包程序入口、固定样本、实际操作与预期                                    |
| 公开分发                                | 原1594签名/公证、干净安装、升级失败回退及凭据验证                         |

当回归触发时，普通review目前只警告；quick/CI未自动强制有效回执。交付须显式执行现行review:changes --require-regression 本轮JSON，核指纹、证据hash和真实通过；1562/1564/1904另处理自动阻断改进。本轮不改规则/检查器。

quick不包含全部集成与桌面；ci的原生e2e为not-run；full现有e2e是工程探针。完整业务链仍消费原领域和1657的验收，不降低安全Fuse以方便自动化。

测试要检验不变量与真实结果。新增故障回归应能在原问题/注入条件下失败，在修复后通过；纯文档和低风险可逆编辑不机械增添镜像测试。
