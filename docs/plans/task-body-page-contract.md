## 1. 当前唯一用户结果

无账号、无Key、无Project创建Task，输入中文内部沟通稿，保存后完全退出进程，再打开同一Task/Document及已保存正文修订。无Key不显示配置阻断。D1只验证人工正文，不展示虚假的材料、AI候选、来源已核验或导出成功。

基础布局只需任务入口/最近任务选择与当前Task工作区；工作区显示标题、目标、成果Document标题、编辑区及保存反馈。任务目标是结构化元数据，成果正文属于Document，不镜像双写。页面布局和视觉组件可由实现细化，身份、保存和失败语义不可因布局改变。

## 3. 正文保存状态及回执关联

| 状态         | 用户可见含义                               | 允许操作/恢复                                    |
| ------------ | ------------------------------------------ | ------------------------------------------------ |
| 读取中       | 尚未拿到当前绑定的已保存内容               | 暂不允许把空编辑器写回；失败可重试读取           |
| 已保存       | 当前编辑内容对应已落盘确认的同一body与修订 | 可以退出；不等于律师定稿、云端同步或Task完成     |
| 有未保存修改 | 当前编辑比最后一次已确认修订更新           | 可继续编辑、提交；显示本机当前尚未确认的内容     |
| 保存中       | 某次提交正在等待确认                       | 新输入继续归未提交内容；不能用旧回执确认后续输入 |
| 保存失败     | 已知该提交未保存成功                       | 输入保留，旧修订可读；显示原因、重试/诊断        |
| 结果待核对   | 超时或断开，不能确定提交是否成功           | 查询原操作结果后更新，不能显示成功或盲目重建对象 |

明确样例：提交A/body-X的r1后继续输入r2，r1成功回执只更新“最后已保存r1”，界面仍显示r2有未保存修改；切到B后，A的回执不修改B。相同修订的显示比较使用1623/1582冻结的保存关联，不把Yjs state vector、对象version或requestId混作保存证明。

Task业务状态、五阶段进展、正文保存状态、Run、候选、正式定稿和交付分别展示。模型成功、接受新稿或导出均不自动完成Task。

## 4. 输入、可达性与取消

- 中文IME组合输入期间不触发提交/导航，不因保存反馈、任务查询刷新而重挂载编辑器或丢焦点；组合结束后按当前内容保存。人工正文不创建WorkRun。
- 鼠标可点入口和保存；键盘Tab可到表单/保存/返回，焦点可见。表单Enter仅在非IME组合态提交；编辑区Enter输入换行；不新增全局抢键快捷键。
- 错误文案说明未保存内容与仍安全保留的内容，提供下一动作，不只靠颜色。错误信息不包含敏感全文、Key或任意文件路径。
- 长标题可视觉截断但须有可访问完整名称；窄窗口保留Task/Document身份和保存状态，不用滚动位置充当业务身份。
- 新建未提交时取消返回原入口；已发送创建后不能用“取消”假称已回滚，结果未知先查询。关闭/切换的取消返回原编辑会话及光标；不默认丢弃输入。
